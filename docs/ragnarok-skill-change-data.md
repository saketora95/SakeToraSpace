# 仙境傳說技能調整資料格式

查詢頁：`ragnarok-skill-changes.html`。資料檔：`assets/js/tools/ragnarok/skill-change-data.js`，以 `window.ragnarokSkillChangeData = { ... };` 載入，不需後端或建置程序。可直接開啟 HTML 或以既有靜態網站部署。

目前資料於 2026-10-05 匯入杜腐的[kRO 迄今技能調整／優化整理](https://forum.gamer.com.tw/C.php?bsn=4212&snA=436731)，來源文章更新於 2026-10-01。完整涵蓋[四之一轉](https://forum.gamer.com.tw/Co.php?bsn=4212&sn=2901200)、[四之二轉](https://forum.gamer.com.tw/Co.php?bsn=4212&sn=2901201)、[擴充職業與喵族](https://forum.gamer.com.tw/Co.php?bsn=4212&sn=2901202)及[非四轉補充技能](https://forum.gamer.com.tw/Co.php?bsn=4212&sn=2901252)四個樓層。來源 19 個職業章節拆為 21 個可篩選職業，詩舞與忍者各自分列，共用技能關聯雙方；非四轉補充技能歸入文章指定的相關職業。

收錄 290 個技能、13 個版本分類、642 筆技能與版本的調整記錄，共 1848 個調整項目。來源本身包含 271 個技能標題與 609 列調整記錄，合併標題拆為獨立技能後產生較多技能與記錄；`meta.source.coverage` 保留逐樓層的章節、標題與原始列數，供完整性檢核。

技能 ID 與多語名稱的核對資料位於 `scripts/ragnarok-skill-metadata.json`，匯入器會自動讀取。依據 [kRO 官方技能目錄](https://ro.gnjoy.com/guide/runemidgarts/skilllist.asp)與 [Divine Pride 客戶端技能資料](https://www.divine-pride.net/database/skill)，目前核定 283 個技能 ID、287 個韓文名稱、200 個英文名稱及 257 個日文名稱；各項證據的網址與適用欄位保留於 `evidence`。名稱與 ID 未能確認時維持 `null`，不以程式內部名稱代替顯示名稱。

邪靈淨化、重力場域、神龜爆裂震、大地綻放、冰晶新星的獨立技能 ID 尚未核定。填裝火焰陷阱與填裝急速陷阱的官方頁面及客戶端 ID 對應有衝突，兩項 ID 與日文名稱也保持 `null`，候選 ID 及衝突來源保留於 `conflictingSkillIds`。這 7 個技能的調整內容仍完整收錄。

版本編號沿用作者分類，不代表官方版本編號。頁面現行版本設定為第 4.2 版本（2024-10-16），匯入器也固定採用此版本，避免重新匯入時改成較新的版本；來源索引缺少此版本或尚未實裝時停止匯入。第 9 版本是 2026-09-30 公布的預定調整，尚未實裝，保留獨立的預告標籤。保留所有有調整的版本及其官方維護公告或開發者筆記連結。隕石術猛擊的一筆調整在來源中標示「未知」，另列「版本未知」，不推定日期，也不納入現行版本標籤的回溯判定。

數值、範圍、次數、技能效果與新增技能資訊分開儲存；條件倍率拆成多列，條件放在 `note`。來源未記載的舊值維持 `null`，不從其他版本推算；固定詠唱時間、冷卻時間、變動詠唱時間、共通技能延遲與持續時間統一使用秒，分鐘數值換算為秒；其餘項目未標示的單位不自行補上。活力之源第 8 版本的抗解除變化是文章引用的玩家測試，使用 `evidence: "player-test"` 並在備註說明官方更新清單未載明。專注瞄準原本測試出的抗位移解除效果已於 2026-09-02 被認定為 Bug 並移除，顯示為修正記錄，不能將來源刪線的敘述當成生效的新值。午夜殞落的疑似倍率筆誤與變身猛禽的速度合計說明保留於備註，這些備註不會被誤標為玩家測試。原文「總倍率」與「基本倍率」數值可能不同，照原文保留，不能直接視為連續的同一數值。

公告 `url: null` 不列出公告標題；若版本尚無公告連結，顯示「官方維護公告連結待補」。填入官方維護公告完整網址後會在頁尾公告索引顯示連結。公告發表日未查證時使用 `publishedAt: null`，不以實裝日代替。

## 重新匯入

將完整討論串存為 UTF-8 HTML，執行以下指令（Python 3.10 以上，僅使用標準函式庫）：

```sh
python3 scripts/import-ragnarok-skill-changes.py --index path/to/full-thread.html --skills path/to/full-thread.html --date YYYY-MM-DD
python3 scripts/test-ragnarok-skill-import.py
node scripts/test-ragnarok-skill-changes.cjs
```

也可用 `--skills` 傳入四個職業樓層 HTML 檔案。匯入器檢查必須的樓層與職業章節，會解開巴哈姆特轉址並保留官方網址；缺少樓層、未知職業、未定義的版本、重複記錄或表格結構異常時停止，不寫入新資料。可明確識別的數值與前後敘述會結構化，其餘描述完整保留為技能效果，避免遺漏原文內容。來源合併的多技能標題拆成獨立技能，共用調整記錄分別關聯。支援 `--output` 指定其他輸出檔案；測試用的部分匯入不應覆蓋正式完整資料。原有示範資料位於 `scripts/fixtures/ragnarok-skill-change-demo.js`，僅供介面測試使用。

## 頂層結構

| 欄位 | 用途 |
| --- | --- |
| `schemaVersion` | 固定為 `1`；資料結構變更時一併更新讀取程式。 |
| `meta` | 資料範圍、現行版本與更新日期。 |
| `jobs[]` | 職業目錄。 |
| `skills[]` | 技能名稱、遊戲 ID 與適用職業。 |
| `versions[]` | 版本目錄與排序。 |
| `announcements[]` | 版本相關官方公告；版本未知時保留來源待確認的佔位。 |
| `records[]` | 技能 × 版本的調整記錄，每筆可有多項調整及多份公告。 |

資料集限單一伺服器，避免混用 kRO、twRO 等不同改版進度。`meta.server` 可填 `kRO`；若日後加入其他伺服器，應使用獨立資料集或擴充伺服器關聯及篩選。

## 欄位規格

- `meta`：`isDemo`（布林值）、`server`（名稱）、`currentVersionId`（對應版本 `id`）、`updatedAt`（`YYYY-MM-DD`）。現行版本由 `currentVersionId` 明確指定，不從最新日期或最大 `order` 推測。`notice`（選填）顯示收錄範圍說明；`source`（選填）包含文章 `title`、`author`、`url`、職業章節 `sectionUrl`、所有來源樓層 `sectionUrls`、來源更新 `updatedAt` 與逐樓層完整性統計 `coverage`。確認正式資料後才將 `isDemo` 設為 `false`。
- `jobs[]`：`id`（穩定字串）、`name`（顯示名稱）。陣列順序即職業選單順序。
- `skills[]`：`id`（內部穩定字串）、`skillId`（遊戲的整數 ID，未知可為 `null`）、`jobIds`（職業 `id` 陣列）、`names`（`zhHant` 必填；`ko`、`en`、`ja` 為韓文、英文、日文，可省略或為 `null`）。`jobIds` 明確列出所有相關職業，包括需要顯示該技能的進階職業；不自動推測技能繼承關係。同一技能只存一份，關聯多個職業。`sourceUrl` 指向原始職業樓層；選填的 `sourceHeading` 保留拆分或正規化前的標題，`metadataSourceUrl` 指向技能 ID 與名稱的核對來源。
- `versions[]`：`id`、`name`、`order`（唯一整數，越大越新）、`releasedAt`（實施日期，`YYYY-MM-DD` 或 `null`）。選填 `status` 可為 `released`、`planned` 或 `unknown`；預告版本必須設定 `announcedAt`（公布日期）、`releasedAt: null`，且不得設為現行版本；未知版本日期為 `null`，不得設為現行版本，也不參與技能現行版本回溯。版本選單、公告及技能歷史皆依 `order` 降冪顯示；預告版本另有「預告・尚未實裝」標籤。
- `announcements[]`：`id`、`versionId`、`title`、`publishedAt`（公告日期，`YYYY-MM-DD` 或 `null`）、`url`（官方公告完整 `http://` 或 `https://` 網址，未知為 `null`）。公告日期與實施日期分開儲存。同版本內公告依陣列順序顯示；應連到支持調整內容的公告本身。
- `records[]`：`id`、`skillId`（對應 `skills[].id`，不是遊戲的整數 ID）、`versionId`、`announcementIds`（至少一份同版本公告或來源佔位）、`changes`（至少一個調整項目）、`sourceUrl`（對應的原始職業樓層）。選填 `evidence` 為 `article` 或 `player-test`，後者需以備註清楚標明測試來源及未確認狀態。同版本可有多筆記錄，依資料中的先後順序顯示；適合補充修正公告。
- `changes[]`：`item`（調整項目）、`before`、`after`（必填，可為數字、字串或 `null`）、`unit`（選填字串）、`note`（選填備註字串）。`null` 代表資料缺漏，顯示為「—」；數字 `0` 會正常顯示。

`unit` 除了 `%` 緊接數值，其餘單位一律與數值保持一個空格。例如 `{ before: 400, after: 450, unit: "%" }` 顯示 `400% → 450%`，其他單位顯示為 `0.5 秒`、`3 格`、`4 次`、`100 HP`；單位原有的首尾空白會先移除，避免多餘空格。單位不一致或公式、範圍、使用條件等內容，直接使用完整字串並省略 `unit`。

係數項目省略「技能倍率中的」，五級武器與重量條件寫為「以五級武器、武器重量 150 計算」，特定狀態條件以「於 xx 狀態下」描述。中文描述與備註使用全形標點，例如 `，`、`：`、`；`、`。`、`（）`。匯入器在解析後統一描述文字的標點，保留小數點、`P.ATK` 等縮寫及數值單位。

## 新增資料範例

以下同樣是假設資料，僅供說明欄位。將各筆加入對應陣列，並填入真實公告網址即可。

```js
// jobs
{ id: "knight", name: "騎士" }

// skills
{
  id: "example-skill",
  skillId: null, // 正式資料應填已確認的遊戲技能 ID
  jobIds: ["knight"],
  names: { zhHant: "範例技能", ko: null, en: null, ja: null }
}

// versions
{ id: "example-patch", name: "範例技能調整", order: 4, releasedAt: null }

// announcements
{
  id: "example-notice", versionId: "example-patch",
  title: "官方維護公告標題", publishedAt: null,
  url: null // 替換為公告完整網址；未確認時維持 null
}

// records
{
  id: "example-skill-patch",
  skillId: "example-skill",
  versionId: "example-patch",
  announcementIds: ["example-notice"],
  changes: [
    { item: "技能倍率", before: 400, after: 450, unit: "%" },
    { item: "發動機率", before: 10, after: 15, unit: "%", note: "僅適用於最高技能等級。" },
    { item: "技能範圍", before: "5 x 5", after: "9 x 9" },
    { item: "使用條件", before: "限定單手劍", after: "單手劍或雙手劍" }
  ]
}
```

版本上線時修改 `meta.currentVersionId`，同步更新 `meta.updatedAt`。各目錄的 `id` 必須在各自陣列內唯一，記錄與公告的版本必須一致。載入程式會驗證參照、日期、重複 ID、數值與網址格式；錯誤會顯示在頁面上，不會悄悄略過資料。網址格式驗證不代表來源真實性，整理資料時仍需確認其為相關官方公告。

## 查詢行為與驗證

未選擇職業、版本、技能且搜尋文字為空時，左側仍列出全部技能，右側先顯示「資料較多，請先篩選」提示與「展開完整資料」按鈕。展開後才產生全部技能表格；套用任一條件或選取單一技能時直接顯示符合資料。重設篩選或清除所有篩選條件後恢復提示。

篩選列與技能右上角的複製按鈕以 `🔗` 表示，滑鼠提示及無障礙名稱保留用途文字；複製成功暫時顯示 `✓`，失敗顯示 `!`，結果也會透過狀態區域朗讀。

篩選列的「複製篩選連結」會複製目前職業、搜尋文字、版本與技能選取狀態；每個技能右上角的「複製技能連結」會改用該技能所屬職業、清除搜尋文字並選取該技能，保留目前版本條件。共用技能優先沿用目前選取的適用職業，否則採職業排序中的第一個。載入連結與變更網址片段時皆套用條件，未知職業、版本及技能參數忽略。

分享參數使用 URL 的 `#` 片段：`job` 為職業 ID、`q` 為搜尋文字、`version` 為版本 ID、`skill` 為技能內部 ID。例如 `ragnarok-skill-changes.html#job=dragon-knight&skill=dk-5201&no=1` 會篩選盧恩龍爵、選取死侍武器並隱藏返回工具箱連結。單獨使用 `#no=1` 也可隱藏返回連結；搭配其他參數時以 `&no=1` 附加。頁面隱藏返回連結時，複製的分享連結會保留此設定。複製優先使用 Clipboard API，無法使用時嘗試相容的複製方式，並回報成功或失敗。

職業、技能搜尋及版本篩選同時套用，支援部分多語名稱、技能 ID、額外搜尋關鍵字、大小寫及全形英數字。技能可在核對資料中設定 `searchKeywords` 字串陣列，匯入器會保留於技能資料；死侍武器系列另可透過 `4457` 搜尋。指定版本後，技能清單及結果只列出該版有調整的技能；點選技能查看單一技能，再次點選同一技能或按「查看全部符合技能」會取消選取，恢復全部符合目前篩選條件的技能。點選其他技能則切換至該技能；點選後焦點保留在該技能按鈕。若切換條件後已選技能不符合篩選，會清除選取。

左側標題顯示「篩選結果　共 x 筆資料」，筆數為符合篩選條件的技能數量。職業選單、左側技能清單與右側資料依指定職業順序排列：盧恩龍爵、帝國聖衛軍、樞機主教、聖裁者、禁咒魔導士、元素支配者、機甲神匠、生命締造者、風鷹狩獵者、天籟頌者與樂之舞靈、十字影武、深淵追跡者、天帝、契靈士、夜行使、流浪忍者與疾風忍者、終極初學者、魂靈師、德魯伊。同職業內依遊戲技能 ID 由小到大排序，未知 ID 排在該職業最後；共用技能以最先列出的適用職業決定排序位置，且只呈現一次。匯入器維持相同的職業與技能排序。

「查看全部符合技能」按鈕保持可點選；查看全部時以金色邊框、選取背景及較粗文字顯示，並設定 `aria-pressed="true"`。查看單一技能時恢復一般按鈕樣式，由該技能按鈕呈現選取狀態。

預設顯示全部版本。指定版本後，只顯示該版本記錄。每個技能優先在現行版本的調整記錄標記「現行版本」；若該版沒有調整，回溯至現行版本之前最近一次調整，標記「沿用至 4.2 版本」。現行標籤使用金色，沿用標籤使用綠色，兩者的資料區塊皆維持相同的金色高亮。現行版本之後的調整不會獲得這兩種標籤；只有較新版本記錄的技能不標記。標籤依完整歷史判定，不隨篩選移到其他記錄。這是變更記錄，並非推算後的完整現行技能數值。

頁面省略頁首查詢說明、「調整內容」標題、結果筆數列、資料來源列、伺服器／現行版本／更新日期列及搜尋輔助文字。資料來源與日期保留於資料檔；正常載入時隱藏狀態列，驗證失敗時顯示錯誤。調整表的版本名稱不附日期，頁尾公告索引仍顯示相關日期。

技能標題下以一列顯示所屬職業、技能 ID、韓文、日文與英文名稱，欄位間以 `‧` 分隔，窄畫面可自然換行。未知 ID 使用 `null`，未知名稱可省略、填 `null` 或空字串，未知職業使用空 `jobIds`；分別顯示 `（缺少技能 ID）`、`（缺少技能韓文名稱）`、`（缺少技能日文名稱）`、`（缺少技能英文名稱）`、`（缺少技能所屬職業）`。

未指定版本且結果區寬度至少 720px 時，每個技能的所有版本合併為一張表格，以版本欄及群組列區分，現行版本列群組高亮。結果區較窄或指定版本時使用各版本獨立表格；縮放視窗會自動切換，保留目前篩選與技能選擇。調整表不重複列出公告，官方連結統一在頁尾顯示。

現行版本標籤在欄位空間足夠時排在版本名稱右側，空間不足才換行。所有調整表共用依目前顯示資料計算的欄寬；計算包含欄名、版本名稱與完整標籤文字、調整項目、前後數值及備註，保留基本可讀寬度並讓較長內容取得較多空間。特別長的內容會換行，避免單一欄位占滿表格；篩選、技能選擇與結果區寬度變更時會重新計算。
